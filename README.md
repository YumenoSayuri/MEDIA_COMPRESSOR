# 本地媒体压缩器（图片 + EchoWave 视频）

- 图片：Sharp 本地处理。
- 视频：Electron 后台 BrowserWindow 实际调用 `https://echowave.io/app/tools/compress`，不使用本地 FFmpeg。

## 视频任务

- 基础方案：轻度、平衡、激进、最大化。
- 高级方案：CRF、分辨率、帧率。
- 视频编码器和音频编码器独立于基础/高级压缩模式，两个模式都可以生效。
- 最多同时运行 2 个隐藏 EchoWave 页面，后续任务自动排队。
- 压缩运行中仍可继续选择视频、导入文件夹或拖放文件，新任务会追加到当前队列末尾，不会增加网页并发数。
- 上传阶段同步显示上传百分比和已上传大小；上传速度与预计剩余时间由本项目根据连续上传样本计算。
- 上传进度采用单调高水位记录。EchoWave 在分片切换或上传最终确认阶段即使把网页数字从 100% 暂时改回较小值，本地列表也不会倒退。
- 网页压缩阶段以 EchoWave 当前页面的 DOM 文案和进度条为准同步读取压缩百分比，并显示当前阶段耗时；不再用本地上传百分比推断网页压缩进度。上传页面切换到网页压缩页面后，立即切换为网页压缩状态。
- 网页状态读取异常不会再被当成“压缩 0%”：连续 15 次无法读取页面会立即结束当前尝试并进入自动重试，同时显示具体读取错误。
- 提交后 3 分钟仍未进入 EchoWave 渲染页会重试；进入渲染页后，明确停在 0% 达 10 分钟、已有进度但 20 分钟不增长，或连续 30 分钟没有提供百分比，都会结束当前尝试并按设置自动重试。单次尝试绝对上限为 2 小时。
- 若网页没有提供百分比，只显示“网页压缩中”，不会拿本地上传进度或页面读取失败冒充压缩 0%。
- 压缩完成后自动下载，并按上传文件的原文件名保存；任务行显示总耗时，不修改结果文件名。
- 应用会拦截 EchoWave 的下载和下载弹出页，直接设置临时保存路径，避免出现系统“另存为”窗口。

## EchoWave 2026-11 改版适配

站点在 2026-11 中旬改版，旧脚本用的选择器和状态文案全部失效，本项目已按实测对齐：

- 提交按钮不再是 `button[type="submit"]`，而是文案为「压缩视频」的普通按钮。上传期间它的文案是「压缩视频 上传完成后开始」，只有上传真正落地后才变成「压缩视频」——现在以此作为上传完成的唯一信号。
- 基础方案文案从「轻度压缩 / 平衡（推荐）/ 激进 / 最大化」改为「轻度 / 均衡 / 推荐 高强度 / 最大」（按钮上还带预估体积，如「均衡 ≈ 22 KB」）。
- 渲染阶段显示「正在压缩… NN%」，进度条是带 `aria-valuenow` 的 div。
- 完成页文案是「你的视频已就绪」，配「下载」「更改设置」两个按钮；旧的「压缩完成 🎉」已不存在。**这正是之前进度条卡在 90% 上下不动的原因**：旧逻辑既等不到「压缩完成」，也找不到 `button[type="submit"]`，只能一直空等。
- 免费额度是**每天 3 次**，按账号（Firebase UID）计数，匿名身份也有 3 次。完成页会显示「今日免费处理还剩 N 次（共 3 次）」，最后一次会提示「这是你今天最后一次免费处理」。
- 额度用尽后整块工具被一张墙取代：「今天的 3 次免费处理已用完 / 免费次数将在午夜恢复」。此时自动化直接报错说明，不再空转等待。
- 下载前后页面可能弹出升级弹窗（URL 带 `?ew_modal=upgrade`），它**不阻断**下载，任务行会标注「页面同时弹出升级提示」。
- 实测免费档导出的成品**不带水印**：把成品逐帧导出比对，48 帧全部为纯色、无角标。

## 必须给隐藏窗口配代理

EchoWave 的登录与匿名鉴权走 Firebase（`identitytoolkit.googleapis.com`）。该域名在中国大陆直连不通，典型表现是刚选完文件就报 `处理错误 not_authenticated`，页面只剩「重试 / 联系支持」。

- 界面「网络代理」默认留空，表示跟随系统代理（本机 Clash 开着系统代理/TUN 时就会自动走通）。若出现 `not_authenticated`，再在这里填 `http://127.0.0.1:7897`。
- 也可用环境变量 `$env:ECHOWAVE_PROXY='http://127.0.0.1:7897'`，界面里的值优先。
- 代理只作用于 EchoWave 隐藏窗口所在的持久分区，不影响本机其他程序。
- 代理不稳时页面会报 `Connection hiccup`，本项目给出「网络抖动（可重试）」提示并按设置自动重试。

## 登录与额度

- 站点免费额度是**每个账号（Firebase UID）每 3 次**，按站点所在的零点重置（实测为 **UTC 00:00 = 北京时间 08:00**），不按 IP。隐藏窗口用的是持久分区 `persist:echowave-video-v2`（**不是无痕窗口**），登录态和匿名 UID 都落在分区的 IndexedDB（`firebaseLocalStorageDb`）里，所以这 3 次跟着分区里的那个身份走。
- 任务行会显示「今日剩余免费 N 次」；第 3 次时站点会提示「这是你今天最后一次免费处理」。

### 额度用尽自动换身份（默认开启）

额度键在 UID 上，所以本项目做成了自动续跑：页面一旦出现「今天的 3 次免费处理已用完」这张墙，就清掉分区里的 Firebase 身份（cookie / localStorage / IndexedDB 里的 auth 记录，顺带清缓存），重新加载页面让站点自动匿名注册一个新 UID，然后**原任务原地重跑**，不需要人工干预。

- 界面开关「额度用尽自动换身份」默认勾选，「次上限」默认 20（可拉到 200）：单个任务最多连续换这么多个身份，每个身份 3 次，等于批量不再受 3 次限制。
- 换身份时任务行会显示「今日免费额度已用完 · 切换第 N 个匿名身份后继续」。
- 保护：连续 3 个新身份仍然撞墙就停下并报错，说明站点已限制本网络建号——换网络出口（切 Clash 节点）或稍后再跑。
- 如果你在里面登录了真实账号：换身份等于把该账号登出。要保住登录态就关掉这个开关，改用「换账号」手动续。
- 边界：这本质是在规避站点的免费额度，匿名建号走的是 Google Identity Toolkit 接口，短时间高频创建可能被限流，表现就是上面那条「连续撞墙」保护。

### 手动登录

- 需要登录或处理验证码时：`$env:ECHOWAVE_SHOW_BROWSER='1'; npm start`，窗口里登录完成后最多等 5 分钟，自动化会自动接着跑。

## 失败与重试

- 除“已完成”和已从列表移除的任务外，排队、上传、网页压缩、下载、失败、停止等状态都会显示 **重试** 按钮。
- 批量任务运行中点击重试，会立即取消该任务的旧隐藏页面，并把同一文件作为新尝试追加到当前队列末尾；旧尝试不会继续占住两个并发槽位之一，也不会污染最终完成统计。
- 可勾选 **失败后自动重试**，并设置自动重试次数（0–5 次）。总尝试次数等于首次尝试加自动重试次数。
- 自动重试用于打开 EchoWave 页面、上传、网页压缩和下载阶段失败。网页压缩 0% 卡死或长时间无增长时，也会按设置次数重新建立页面任务。
- 下载触发失败时会先在当前页面内自动重新触发下载，仍失败时再按设置次数重新建立页面任务。
- 自动重试开关和次数会与其他视频设置一起持久化，重新启动应用后继续保留。

## 保存方式

1. **源路径保存副本**：`原文件名-副本.ext`，重名自动递增。
2. **固定输出路径**：保存到指定目录，导入文件夹时保留相对目录结构。
3. **直接替换原文件**：先写入临时文件，下载完成后再替换原文件，避免中途损坏源文件。

## 暂停、停止与移除

- **暂停队列**：不再启动排队中的新任务；已经提交到 EchoWave 的远程任务继续运行。
- **停止全部**：关闭当前正在运行的后台 EchoWave 页面并取消下载；未开始的任务保留为“待处理”，不会伪装成“已停止 100%”。再次开始时，所有未完成任务会立即重置为排队状态。
- **移除**：每一行任务都可以随时移除，包括运行中、暂停中和停止过程中。移除运行中任务会取消对应页面/下载；移除排队任务不会启动它。

## 设置持久化

视频的基础/高级模式、压缩方案、CRF、分辨率、帧率、视频/音频编码器、保存方式、固定输出路径、自动重试开关及次数都会保存。

## 运行

```powershell
npm install
npm start
```

默认隐藏 EchoWave 页面。需要查看页面或处理登录/验证码时：

```powershell
$env:ECHOWAVE_SHOW_BROWSER='1'
npm start
```

登录状态保存在 Electron 持久分区 `persist:echowave-video-v2` 中。该新分区用于避开旧版本可能残留的缓存、Service Worker 或损坏会话。
